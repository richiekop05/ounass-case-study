# Discovery: how ounass.ae exposes product data

Generated by `scraper discover` on {{generated_at}}. User-Agent: `{{user_agent}}`.

## Decision

**Extraction method: embedded JSON (`source = "embedded"`).** Every listing and product page
is server-rendered with the full app state in an inline script, `window.initialState = {...}`.
The scraper reads that object with a JSON decoder. It does no HTML scraping and runs no
headless browser.

Checked in the PRD's order:

1. **A JSON response for the same URL: not used.** The suggested `?ajax=true` URL is
   disallowed by robots.txt (`/*ajax*` and `/*?*`), so it was not tried.
2. **JSON embedded in the HTML: works.** `initialState.plp` on listing pages and
   `initialState.pdp` on product pages. There is also one JSON-LD block, but it has
   less data, so it is not used.
3. HTML parsing and 4. a headless browser: not needed.

## robots.txt

The scraper obeys every rule below. They have three practical effects:

* **No query strings at all.** `Disallow: /*?*` blocks every URL with a `?`. Both PRD leads,
  `?fh_start_index=24` (pagination) and `?ajax=true` (JSON), are disallowed. The file itself
  warns: "Do not remove Disallow:/*?* rule".
* **Only the first 24 products of each listing are reachable.** Without pagination, the plan
  gets variety from many narrow category pages instead (for example
  `/women/jewellery/fine-jewellery/earrings/studs`). Clean category paths are allowed, and the
  sitemap lists about 1,300 of them. The PRD rule "take every nth product across the first
  few listing pages" becomes "every 3rd product across page one, then offset by one".
* **No crawl delay for `User-agent: *`.** The 10-second crawl delay applies only to named SEO
  bots. The tool keeps its own 1.5 to 2.5 second gap between requests.

## Site terms

Checked at `/content/terms-and-conditions`. The terms have **no clause on automated access,
scraping or robots.** The relevant clauses are:

* Intellectual property: "Any reproduction or redistribution of the Content is prohibited ...
  copying and use of the above listed materials on any other server ... for publication,
  reproduction or distribution is expressly prohibited. However, you are permitted to make one
  copy for the purposes of viewing Content for your own personal use."
* Personal use only: "The Website is for customers' personal use only."

So collection is not prohibited, and the PRD's stop rule is not triggered. Copying images and
text to Supabase is a gray area under the reproduction clause, though. The PRD's mitigations
cover it as far as a prototype can: a private bucket, signed URLs, about 250 products,
non-public use, and a disclosure line in the case write-up. **Flag this to the case reviewer.**

## Product page

`{{product_url}}`

* URL pattern: `/shop-<brand>-<name>-for-<audience>-<parentSku>_<colourId>.html`. That confirms
  the PRD lead. The trailing `<parentSku>_<colourId>` is `styleColorId`.
* **`product_id` = `styleColorId`** (for example `220163574_195`). The PRD counts each colour as
  its own product, and `parentSku` is shared across colours, so `parentSku` is kept as a
  separate column for the one-colour-per-style rule.
* Canonical URL: `<link rel="canonical">`, the same as the clean product URL.
* Breadcrumb: `pdp.breadcrumbs`, every level down to the deepest site category; the last entry
  is the product itself and is dropped.
* Price: `pdp.price` in `initialState.currency` (AED). `slashedPrice` holds the original price on sale items.
* Images: `pdp.media[].src` are paths under `https://ounass-ae.atgcdn.ae/.../pub/media/catalog/product`.
  The CDN resizes on the fly with a `small_light(...)` path segment. The scraper uses
  `small_light(dw=1000,of=jpg)`, which returns a 1000 x 1500 JPEG. The CDN has no robots.txt
  (404), so no rules apply. The `?ts=` cache-buster is dropped.

### Tabs

**All tabs are in the page response**, not only the open one. They are in `pdp.contentTabs[]`
as HTML fragments, plus a structured `pdp.deliveryDetails`. No separate request is needed.
Labels as shown on this page:

| tabId | Label on the page | Content |
| --- | --- | --- |
{{tab_labels}}

* `description` holds the editor's notes and maps to `description`. Paragraphs are joined with a blank line.
* `designDetails` holds one `<p>• line</p>` per line and maps to `details`. The leading "• " glyph
  is dropped and the wording is kept. The last line is the style code ("Product Code: ...").
  Lines shaped `Label: value` also go into `attributes`.
* `sizeAndFit` maps to `size_and_fit`, the same way.
* **Beauty pages have different tabs.** A fragrance page (fixture
  `product_beauty_fragrance.html`) has `description` "Editor's advice", `keyDetails`
  "Key Details" and `ingredients` "Ingredients", with no Design details and no Size & Fit.
  `keyDetails` plays the Design details role (size, concentration, ...), so it maps to `details`.
  Ingredients is kept in `content_tabs` only.
* Every tab, including delivery, also goes into `content_tabs` as `{label, text, items}`.

## Bot protection

Plain HTTP requests with a truthful user agent got 200 responses and full pages. The state
mentions Kasada (`kasadaEnabled: false`), so the scraper treats any 403, any page containing
"captcha", or any product or listing page without `window.initialState` as a block, and stops.
